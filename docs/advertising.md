## 尺寸与显示

- 按 **300 × 105 逻辑像素**申请 20:7 横幅，水平居中，底部避开安全区并再留 8 像素。高度通过比例预留，**不向 SDK 写入不支持的 height**。
- 微信官方接口定义没有给出此 CustomAd 模板通用的最小尺寸，且 width / onResize 仅对部分模板生效。因此 300 不是已验证的平台最小值；若 SDK 回传实际宽高，以回传值重新排版。真机验收还需确认该广告位的尺寸限制。卡片不裁切、拉伸或遮盖关闭控件；若完整卡片放不下，则不展示。
- 工具区缩至原来的 88%；优先收紧棋盘上方与行间空白，保持补货碟间隔，短屏仍不足时等比缩小棋盘。适配包含两行、三行和四行关卡。
- 原生广告高于 Godot 画布，打开任意游戏弹层时隐藏，不用 Canvas 遮罩假装遮住广告。模板不支持 `hide()` 时销毁，回到游戏后按需重建。用户主动关闭后本局不立即重开；无填充等加载错误后不在同一局反复创建。
- 广告初始化安排在第一帧绘制后，不加入引擎或资源包启动等待链。微信 `onHide/onShow` 同时通知广告桥接和既有焦点处理，广告期间音乐、音效、震动暂停，回前台且广告流程结束才恢复。

## 奖励与存档

`platform/wechat/ads.js` 管理 SDK 实例、展示互斥、回调去重和尺寸；`scripts/core/game_ads.gd` 把原生回调延迟到 Godot 主循环；页面流程在 `scripts/game_app.gd`。

完成激励视频后先保存待领取回执，再由 `SaveStore.grant_ad_bag()` 将库存与最后已领取回执作为同一快照提交；提交成功才确认回执。保存失败时库存回滚，点击原按钮可以重试领取，无需再看视频。冷启动发现未确认回执时再次交给存档层处理，已提交的回执不会重复发奖。重复点击不会并发播放。

这是设备本地存档，不是服务器验签或跨设备奖励服务；微信存储和存档同时不可写、或清除应用数据时不能保证奖励恢复。取消观看不发奖；无广告提示「广告尚未准备好」。

## 验证与待验收

- SDK mock：广告位、首次预加载、未就绪/失败/超时、一次重试、提前关闭、完整观看、重复回调、互斥、冷却、冷启动回执恢复、尺寸回传、迟到 Promise、前后台及销毁。
- Godot 实际场景：里程碑与存档先后顺序、重玩与历史关卡不补播、失败放行、后台不开始下一关、奖励不自动使用、存档失败重领、不同窗口的盘碟/工具/广告边界、教学聚光按钮坐标。
- 运行命令：`node --test tests/wechat_ads.test.cjs tests/wechat_lifecycle.test.cjs`；Godot 原生运行 `tests/ads_system.gd -- --test-session`。预览可加 `--capture-ads=build/previews/YYYY-MM-DD/ads`，其中广告区域为明确标注的布局示意，非真实广告。
- 真机需验证：iPhone 与安卓实际横幅尺寸/安全区；第 3 关结果页下一关的插屏关闭及无填充；打包袋视频完整观看 +1、提前关闭不加、返回后音乐续播、切后台不扣游戏时间，以及重启后库存保留。开发者工具的 mock 或原生 Godot 检查不能证明线上填充、收益和手机广告播放成功。

接口依据：[微信官方小游戏 API 类型定义](https://github.com/wechat-miniprogram/minigame-api-typings/blob/master/types/wx/lib.wx.api.d.ts)，包含 CustomAd、InterstitialAd、RewardedVideoAd 的接口与事件说明。微信文档网页在本次工具环境中访问受限，未据此宣称横幅最小尺寸已经核实。
