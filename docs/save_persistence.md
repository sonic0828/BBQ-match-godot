# 微信存档修复与合并验收

## 故障与修复

用户反馈三台手机重进后回到各自旧关卡，iPhone 16 Pro 重复打包袋教学，兑换金币也回退。`SaveStore` 将关卡、设置、钱包、库存、每日额度、教学和奖励去重序号写入同一份快照。`933d5a4` 引入临时文件替换，早于本优化分支；未发现优化分支清空玩家数据。

固定 `minigame4.7.0.8.tpz` 的 WXMEMFS 在重命名时先修改内存节点，再计算源路径，实际将目标文件重命名为自身；底层异常也被吞掉。原模板函数可复现“保存返回成功，重启仍读旧文件”。此前桌面存档测试未覆盖此微信适配层。

`platform/wechat/filesystem-patch.js` 由导出脚本注入固定引擎，模板 SHA-256 和注入位置均受检查：

- 先使用原路径执行微信磁盘重命名，成功后才更新内存节点；失败返回文件系统错误，保留旧目标。
- 写文件仅保存有效字节，避免把扩容缓冲的尾部 NUL 一并落盘。截断空文件也必须实际写入。
- 新 `.pending` 快照写入后通过微信文件接口回读比对。关闭文件时发生的错误传递到替换阶段，避免 `ConfigFile` 调用方误判成功。
- `SaveStore` 保留整份快照提交和业务失败回滚；没有添加退出时异步保存，也不依赖微信退出回调才能落盘。

## 旧数据保护

- 新保存使用 `progress.cfg.pending`，旧 `progress.cfg.tmp` 不覆盖、不删除。
- 只有正式存档尚无新格式标记、旧临时文件修改时间严格更新、且关卡／设置／经济字段完整有效时，才恢复整份旧临时快照。时间相同或字段不完整时继续使用正式存档，不拼接字段、不取金币最大值。
- 存在旧 `.tmp` 时，首次覆盖正式存档前，将正式文件原始字节保存在 `.legacy-backup`；备份失败则不覆盖正式文件。
- 新正式存档有 `storage.format=1` 标记，以后不再被遗留 `.tmp` 回滚。新 `.pending` 可能属于已回滚的失败交易，绝不自动恢复。
- 无法承诺找回已被旧版本覆盖的数据。验收前不要清缓存或删除小游戏存档，也不要再用旧 B／D 包交叉写同一份存档。
